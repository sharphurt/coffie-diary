# Мой кофе

Личный кофейный дневник по [ТЗ](docs/spec.md). **Текущая версия 0.1 — начало реализации, не законченная V1.** Данные хранятся в PostgreSQL, клиент работает через Spring REST API. Внешний AI не требуется. Публичное развёртывание не выполнялось.

## Уже работает

- Вход одного владельца, cookie-сессия, CSRF, выход, bcrypt, ограничение попыток входа.
- Создание личного лота и активной пачки 250 г одной транзакцией, повторные покупки.
- Несколько активных пачек, запас, завершение и повторное открытие с журналом переходов.
- Независимый учёт выпитого: выбранная пачка или неизвестный кофе, снимок объёма.
- Оценка 1–5, шесть необязательных шкал с тремя состояниями, комментарий, повторная покупка.
- Оценивание уже учтённой чашки или явное одновременное создание чашки и оценки.
- Мягкое удаление/восстановление, сохранение статистики при удалении пачки/оценки.
- Итоги по локальному периоду Asia/Yekaterinburg, смена объёма профиля без изменения истории.
- Идемпотентные POST, проверка owner, optimistic locking для реализованных изменений.
- Адаптивный React-интерфейс, история с пагинацией.

## Запуск с Docker Compose

Нужен Docker Engine с Compose v2. На проверочном компьютере Docker отсутствует; контейнерную сборку пока не проверяли.

1. Скопируйте `.env.example` в `.env`.
2. Укажите разные случайные `POSTGRES_PASSWORD` и `OWNER_PASSWORD` (не менее 12 символов).
3. Выполните `docker compose up --build -d`.
4. Откройте http://localhost:8080, войдите с `OWNER_LOGIN` и `OWNER_PASSWORD`.

Владелец создаётся только на пустой БД. Изменение переменной после первого старта не меняет его пароль. Сессия живёт до 8 часов и теряется при перезапуске приложения. База сохраняется в именованном volume. **Не выполняйте `docker compose down -v` для среды с нужными данными.**

Логи: `docker compose logs -f app`. Миграции выполняет Flyway при старте. Обновление: сохранить backup, затем `docker compose up --build -d`.

## Разработка без Docker

Java 21, Maven 3.9.11+, Node 24.20.0 и PostgreSQL. Создайте БД `coffee`. Перед запуском задайте:

```text
DATABASE_URL=jdbc:postgresql://127.0.0.1:5432/coffee
POSTGRES_USER=coffee
POSTGRES_PASSWORD=<пароль БД>
OWNER_PASSWORD=<пароль владельца>
```

```sh
cd backend
mvn spring-boot:run
```

В другом терминале:

```sh
cd frontend
npm ci
npm run dev
```

Vite проксирует `/api` на localhost:8080. Frontend собирается через `npm run build`; Dockerfile включает эту сборку в jar. Временные локальные JDK/Maven/PostgreSQL для проверки находятся в `.tools/`, не входят в git и не требуются в Docker.


Smoke запускается **только на отдельной тестовой базе**: создаёт записи с префиксом TEST. Передайте `BASE_URL` и `OWNER_PASSWORD` через окружение; по умолчанию он читает локальный тестовый секрет из игнорируемой `.tools/test-password`. Тест не очищает чужие данные.

Фактически проверено 13.11.2026: компиляция Java, 6 JUnit-тестов, production build frontend, API smoke на PostgreSQL 18.6 и ручное создание пачки через браузер. Подробнее: [приёмка](docs/acceptance.md).

## Резервная копия базы текущей версии

На время копирования остановите приложение, оставив БД работающей:

```sh
docker compose stop app
docker compose exec -T db pg_dump -U coffee -d coffee -Fc -f /tmp/coffee.dump
docker compose cp db:/tmp/coffee.dump ./coffee.dump
docker compose start app
```

Для восстановления используйте **новый отдельный Compose project и пустую БД**, не рабочую базу:

```sh
docker compose -p coffee-restore up -d db
docker compose -p coffee-restore cp ./coffee.dump db:/tmp/coffee.dump
docker compose -p coffee-restore exec -T db pg_restore -U coffee -d coffee --no-owner /tmp/coffee.dump
```

Не запускайте одновременно два приложения на одном порту. Восстановление пока не проверено. Загрузки фото ещё нет, поэтому это инструкция только для базы текущего прототипа, **не полный backup/restore из ТЗ**. Секреты храните отдельно от dump; экспорт и смена/сброс пароля ещё не реализованы.

## Сквозные браузерные тесты

Установите frontend-зависимости и Chromium:

```powershell
npm --prefix frontend ci
cd frontend
npx playwright install chromium
cd ..
./tools/e2e.ps1
```

`tools/e2e.ps1` требует PowerShell 7, Java 21, Maven и PostgreSQL с `initdb`/`pg_ctl`. По умолчанию использует локальные инструменты из `.tools`; для другой установки передайте `-JavaHome`, `-Maven` (путь к mvn.cmd) и `-PgBin`. Эти инструменты не входят в репозиторий.

Скрипт собирает production frontend и backend, запускает **новую отдельную БД** в `.tools/e2e/<UUID>/db` и сервер на 127.0.0.1:18089. PostgreSQL использует порт 55439. Занятые порты вызывают остановку запуска; существующая база не используется и не очищается. Тестовые пароли создаются случайно. После прогона процессы останавливаются, БД и логи остаются для диагностики.

Для уже запущенного отдельного тестового окружения на любой ОС задайте `E2E_BASE_URL` и `OWNER_PASSWORD` (владелец `owner`), затем выполните `npm --prefix frontend run test:e2e`. Тесты создают данные с префиксом E2E и меняют настройки тестового владельца: рабочее окружение для них не подходит.

Два сценария выполняются в Chromium при 1280×720 и 390×664 CSS px (мобильная эмуляция iPhone 13, не Safari):

- Создание пачки 250 г и сохранение после перезагрузки, чашка, оценка из истории без двойного учёта, UNKNOWN/UNANSWERED, удаление/восстановление оценки и чашки, завершение/открытие, повторная покупка, неизвестный кофе 200 мл, выход.
- Отмена формы, пачка в запасе и её открытие, отдельная оценка без чашки, изменение объёма в настройках.

API не подменяется. Первый сценарий отключает `randomUUID` в браузере для регрессии HTTP/LAN. Проверяются ошибки JavaScript, ответы реального API и отсутствие горизонтальной прокрутки основного экрана. HTML-отчёт: `frontend/playwright-report/index.html`; при падении screenshot и trace находятся в `frontend/test-results/`.

Результат 14.11.2026: **4/4 E2E, 9/9 frontend unit/component, 8/8 backend JUnit**, production build PASS. Исправлены пустой ответ восстановления (теперь HTTP 204) и лишнее обновление защищённых данных после выхода. Это покрытие основных реализованных действий, а не всей приёмки V1; остальные незавершённые функции перечислены в матрице приёмки.


### Быстрый учёт на карточке

«Выпил чашку · 250 мл» теперь сохраняет чашку одним нажатием. В сообщении доступны «Отменить чашку» и «Оценить чашку». Закрытие анкеты оставляет чашку учтённой, сохранение оценки не создаёт новую чашку. Пока запрос выполняется, повторное нажатие заблокировано. После сетевой ошибки используйте «Повторить запись чашки»: отправляется тот же ID и объём, поэтому даже потеря ответа после успешной записи не создаёт дубль. Новое действие после завершения получает новый ID. «Выпил другой кофе» по-прежнему открывает форму для произвольного объёма и названия.

Дополнительный E2E-сценарий проверяет потерю реального ответа сервера, безопасный повтор, отмену и оценку из сообщения. Актуальный результат: **6/6 E2E, 9/9 frontend, 8/8 backend**, сборка PASS.

Во вкладке «Выпито» даты фильтруют список и итог по локальному времени владельца. Обе даты включаются в период. Кнопка «Сегодня» сбрасывает период и возвращает на первую страницу. В удалённых записях итог скрыт, поскольку удалённые чашки исключены из статистики.
