## История прогонов

Сверка на `644fd5b`: production-сборка, 10 E2E-проверок в desktop/mobile Chromium на отдельной PostgreSQL, 9 тестов фронтенда и 8 тестов бэкенда прошли. Доказательства из smoke в таблице опираются на существующие проверки и их предыдущий прогон.

### Дополнительная E2E-проверка — 14 ноября 2026

`frontend/e2e/diary.spec.ts`: два сквозных сценария × desktop/mobile Chromium = 4 PASS (11,4 с без сборки и запуска стенда). Production frontend + Spring Boot + отдельный PostgreSQL 18.6, реальные HTTP/cookies/CSRF, без mock API. Мобильный viewport — 390×664 CSS px; desktop — 1280×720. Также 9 frontend-тестов и 8 JUnit проходят.

Проверены создание пачки, повторная покупка, отдельная оценка, состояния UNKNOWN/UNANSWERED, неизвестный кофе 200 мл в дневнике с лотами, оценка учтённой чашки, удаление и восстановление, переходы статуса, отмена формы, настройки и выход. Полнота покрытия приведена в таблице выше. Сценарий отключает `randomUUID`, проверяя регрессию HTTP/LAN.

Исправления: восстановление отвечает 204 вместо пустого 200 (клиент больше не падает при JSON parsing); после logout клиент не запрашивает защищённые данные. Запуск и диагностические артефакты описаны в README. Статусы требований, которые включают ещё не реализованные функции, не повышены до PASS; тест не подтверждает все viewport из AC-41, Safari/Firefox или полную security-приёмку AC-40.


### Быстрый учёт чашки — 14.11.2026

Реализован раздел 11.3: одно нажатие на карточке, блокировка на время запроса, сообщение с отменой и оценкой существующей чашки. При ошибке результат помечается неподтверждённым; повтор отправляет прежние clientEventId и объём. Новое намеренное действие после завершения получает новый UUID. Ошибка обновления счётчиков после успешного POST не выдаётся за ошибку сохранения.

`quick cup: lost response retries once, undo and rating notification` в `frontend/e2e/diary.spec.ts` выполняется на desktop и mobile с реальным API: первый POST доходит до БД, его ответ обрывается, повтор возвращает тот же event; count не удваивается. Проверены отмена, новый ID следующего действия, закрытие анкеты без потери чашки и оценка без нового event. Итого 6 E2E PASS, 9 frontend PASS, 8 backend PASS; production build PASS. Полный выбор профилей и редактирование events ещё не реализованы.

### Маршруты API

Пути ниже относительны к `/api/v1`.

| Группа | Есть | Отсутствует или реализовано частично |
|---|---|---|
| Вход и настройки | `POST /auth/login`, `POST /auth/logout`, `GET /auth/me`, `GET /auth/csrf`, `GET/PATCH /profile` | `POST /auth/change-password` отсутствует. Профиль редактирует имя, объём и обычный рецепт. Часовой пояс и фильтры через него не редактируются. Все четыре операции `GET/POST /brew-profiles`, `PATCH/DELETE /brew-profiles/{id}` отсутствуют. |
| Лоты | `GET/POST /lots`, `GET/PATCH/DELETE /lots/{id}`, `POST /lots/{id}/restore` | Связь с каталогом относится к этапу 3. |
| Пачки | `GET/POST /bags`, `GET/PATCH/DELETE /bags/{id}`, `POST /bags/{id}/status`, `POST /bags/{id}/restore`, `GET /bags/{id}/status-history` | Нет `PUT /bags/{id}/final-impression` и `PUT /bags/{id}/photos`. |
| Фото | Есть таблица метаданных | Нет `POST /media`, `GET/DELETE /media/{id}`. Не реализованы обработка EXIF и хранение файлов. |
| Оценки | `GET/POST /tastings`, `GET/PATCH/DELETE /tastings/{id}`, `POST /tastings/{id}/restore` | PATCH меняет оценку, шкалы, повторную покупку и комментарий. Рецепт отдельной оценки через интерфейс не редактируется. |
| Чашки и статистика | `GET/POST /consumptions`, `GET/PATCH/DELETE /consumptions/{id}`, `POST /consumptions/{id}/restore`, `GET /consumption-stats` | Нет `PUT/DELETE /consumptions/{id}/tasting-link`. PATCH правит время, объём и заметку. В статистике есть диапазон и часовой пояс владельца, остальные фильтры ТЗ отсутствуют. |

OpenAPI описывает только вход, сессию, списки и создание пачек и чашек, а также статистику. Полного контракта для уже реализованных операций пока нет. Каталоги, рекомендации, wishlist и экспорт оцениваются в следующих этапах.

### Пробелы тестового покрытия

- **Этап 1.** Нужны сценарии работы с несколькими профилями, загрузки фото с ориентацией и очисткой метаданных, проверки доступа другого владельца и сохранности файлов после перезапуска.
- **Этап 2.** Нужны сценарии подробного рецепта, явной привязки и отвязки оценки, отказа для чужой пачки и повторной связи, поиска и фильтров с пагинацией, итоговой оценки пачки, рейтинга лота. Отдельно нужны проверки восстановления удалённых лотов и пачек и их связанной истории.
- **Оба этапа.** Текущие тесты проверяют отдельные конфликты версий, повторы запросов и границы суток. Нет систематических проверок параллельных операций, изоляции двух владельцев и границ всех входных полей для каждой операции. Запуск E2E покрывает desktop/mobile Chromium. Сенсорные шкалы и фото на всех ширинах AC-41 ещё не подтверждены.
