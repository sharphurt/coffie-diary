# Рекомендации

## Быстрая подборка FOLK

`GET /api/v1/recommendations` выдаёт до трёх карточек FOLK. Для старта свяжите оценённый лот с товаром через «История → Лоты → Связать с товаром». Достаточно одной оценки. Если импорт уже выполнялся, обновите каталог FOLK, чтобы загрузить профиль обжарки и данные о наличии фасовок. Импорт Tasty Coffee временно отключён.

При оценке от 4 подбираются близкие варианты, при оценке до 2 — контрастные. Промежуточная оценка даёт похожие варианты для сравнения. Для дескрипторов и обработки применяются веса 3 и 2. Контраст строится по различиям между двумя опубликованными признаками. Итоговая оценка пачки имеет приоритет перед средней оценкой её чашек, оценённые пачки одного товара имеют равный вес. Отзывы и личные сенсорные шкалы в этой выдаче не используются.

По умолчанию доступны товары для фильтра и универсальной обжарки. Для эспрессо есть отдельный выбор, для неизвестного профиля — переключатель. Бюджет применяется к реальной цене фасовки в пересчёте на 250 г. При отсутствии подтверждённого наличия или после 48 часов с импорта показывается «Проверить у FOLK». Заведомо недоступные фасовки, цены выше бюджета и товары старше 7 дней исключены. При отсутствии опоры или сравнимых вариантов показывается подборка для знакомства.

## Расширенная модель §13

Ниже описаны ранее реализованные компоненты расширенной модели. Текущая выдача использует быструю подборку FOLK.

Первый шаг раздела 13 — подборка «Для знакомства». `GET /api/v1/recommendations` возвращает `mode: DISCOVERY`, до 10 подходящих товаров и отдельный список `needsCheck` по запросу. Показываются ссылка производителя, вес и цена выбранной фасовки и опубликованное описание. Бюджет сравнивается с ценой за 250 г.

Пока каталоги не сохраняют структурированный профиль обжарки, зерновые товары доступны через `includeUnknownRoast=true`. `includeUnverified=true` открывает предложения с неизвестным наличием или неподтверждённой ценой при заданном бюджете. Свежесть определяется по последнему успешному наблюдению товара, пороги по умолчанию 48 и 168 часов. Порядок стабилен в пределах местной даты владельца и учитывает источник и первую нормализованную группу дескрипторов. Связанные с текущими неудалёнными пачками товары исключаются у их владельца.

Персональная выдача использует одну опору на связанный товар. Итоговая оценка пачки имеет приоритет, иначе берётся среднее оценок совместимых чашек. Неуверенная оценка чашки получает коэффициент 0.5 при усреднении внутри пачки. Затем оценки пачек усредняются с равным весом. Используются фильтр-методы без указанных добавок; неизвестный метод или добавки снижают надёжность до 0.5, если в пачке нет оценок с подтверждённым методом и отсутствием добавок. Оценка без подтверждённой версии дополнительно получает коэффициент 0.5; показывается предупреждение о версии.

Импорт обработки использует поле «Обработка» в характеристиках FOLK и `processing_method` карточки Tasty Coffee. Код обработки участвует в ревизии. Сходство по дескрипторам и обработке — Jaccard с весами 3 и 2. Покрытие нормировано на полные веса §13.4 (11), пороги 0.35 и 0.45. Пять лучших опор взвешиваются по similarity² × coverage × reliability. Для прогноза общей оценки используется prior с весом 0.5. Прогноз каждой личной шкалы требует двух опор; taste fit появляется при трёх общих шкалах с хотя бы одной опорой с рейтингом от 4. Карточки объясняют совпадения и приводят ссылки на опорные товары.

Блок отзывов сравнивает только общие шкалы со статусом CONSENSUS. Совпадающие категории дают 1, соседние 0.5, противоположные 0. Среднее входит в сходство с весом 0.75 для одной общей шкалы и 1.5 для двух и более; тот же вес входит в покрытие. UNKNOWN и CONFLICTED исключаются из обоих расчётов. Сводка строится по доступной выборке отзывов на уровне товара, с теми же порогами, что и диагностический API. В «Почему этот кофе» видны категории, число независимых авторов и ссылки на источники, поддержавшие согласованную категорию у каждого товара.

Версия пачки и остальные внешние признаки пока не участвуют в расчёте. Для категорий производителя ещё нет нормализованного источника для подстановки в сенсорный блок. Далее нужны полные фильтры, подтверждение версии пачки, режим повторных покупок, неизменяемые RecommendationRun и сравнение с producer-only baseline. ConsumptionEvent без оценки остаётся вне расчёта.
