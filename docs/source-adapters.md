Импорт запускается вручную из «Что попробовать». Пустой ответ или ошибка не заменяют сохранённый каталог. Повторное получение того же канонического URL обновляет строку без смены её ID. Импорт не объявляет пропавшие позиции распроданными. Переходы по редиректам отключены. «История → Лоты → Связать с товаром» ищет URL в уже загруженном каталоге и показывает кандидата перед сохранением. Автоматический импорт, полный обход категорий, фасовки, ревизии, разбор дескрипторов и отзывов, нормализованный fallback остаются открытыми. Сетевой прогон на отдельной тестовой БД включается переменной E2E_LIVE_CATALOG=true при запуске tools/e2e.ps1.

Фактический прогон 16 ноября: приложение импортировало 12 позиций FOLK и 11 Tasty в PostgreSQL. Интеграционный тест проверил поиск по URL, подтверждение и снятие связи, а также запрет привязки к чужому лоту. Прогон содержит 10 браузерных тестов и 11 тестов бэкенда.

## Расширенный обход и фасовки, 16 ноября 2026

- FOLK: обход публичной карты товаров с пределом 100 карточек. На карточке используются название и опубликованные поля «Формат» и «Вес» из данных товара. Цена берётся из того же варианта, что и вес. Если вес нельзя однозначно прочитать, пересчёт пропускается.
- Tasty Coffee: общий каталог и последовательные страницы с параметром page, до 24 страниц. Обход останавливается, когда страница перестаёт добавлять новые товары. Ссылки вне раздела кофе пропускаются. На странице товара отдельный Offer даёт цену, валюту, наличие и «Вес упаковки», если он указан. Вид определяется по явному описанию продукта, при отсутствии сведений остаётся неизвестным.
- В PostgreSQL варианты сохраняются отдельно друг от друга в массиве offers. Для каждого предложения с известными граммами и ценой в RUB вычисляется цена × 250 / вес с округлением до копеек. Неоднозначная цена сохраняется как исходный текст. Цена товара из списка без привязки к весу не пересчитывается. В интерфейсе видны вес, цена самой пачки и расчётная цена за 250 г.

Живой расширенный импорт подтвердил 45 карточек FOLK и 172 карточки Tasty. Для каждого источника тест прочитал сохранённое предложение зернового кофе на 1000 г, проверил нормализацию от фактической цены и повторил поиск и подтверждение привязки к лоту.

## Ревизии товаров и неудачные прогоны

Миграция V7 создаёт первый снимок для уже импортированных товаров. Следующий импорт сохраняет прежний ID товара и его связи с личными лотами. Новая ревизия появляется при изменении названия, вида, цены, валюты, наличия или предложений. Порядок вариантов и время повторного наблюдения сами по себе не создают ревизию. Прежний снимок остаётся доступным в БД, а API товара возвращает current_revision_id.

tools/e2e.ps1 запускает CatalogPersistenceTest на отдельной PostgreSQL с синтетическими данными. В сценарии есть повтор той же выборки с другим порядком фасовок, изменение товара, пропуск ранее виденной позиции, пустой результат, исключение загрузчика и ошибка записи после первой успешной строки в транзакции. Отзывы и их дедупликация остаются отдельной частью AC-25.

## Отзывы Tasty Coffee

Серверный HTML карточки содержит счётчик, а тексты доступны в публичной вкладке «Комментарии» после отрисовки в Chromium. Импортёр открывает вкладку обычным браузерным переходом и читает отрисованный DOM. Прямых запросов к закрытым robots.txt маршрутам он не делает. Сохраняется текст родительской карточки с явной ссылкой на этот же канонический товар. Имена, аватары и ответы под карточкой не сохраняются. Дата публикации и ревизия не устанавливаются по догадке, сохраняется время наблюдения.

Ручной запуск для уже импортированной карточки: установите зависимости frontend и Chromium для Playwright, задайте E2E_BASE_URL и OWNER_PASSWORD (при необходимости OWNER_LOGIN), выполните:

    node tools/import-tasty-reviews.mjs https://shop.tastycoffee.ru/coffee/braziliya-sul-de-minas

Обрабатывается видимая порция, до 50 текстов. PostgreSQL дедуплицирует по ID товара и SHA-256 текста после нормализации Unicode и пробелов. Пустая или недоступная вкладка выставляет UNAVAILABLE и сохраняет предыдущие отзывы. До первой попытки статус UNKNOWN. FOLK остаётся UNKNOWN. Автоматический обход всех отзывов и анализ их содержания остаются отдельными задачами.

Признаки отзывов доступны в GET /api/v1/catalog/products/{id}/review-features. Правила ru-rules-v1 возвращают измерение, категорию, фразу-основание, хеш отзыва и URL. Из последних 500 уникальных текстов каждый даёт максимум одно наблюдение на шкалу; противоречивые утверждения об одной шкале пропускаются. Ответы и отмеченные сотрудники исключаются при сборе, известные служебные фразы и логистические высказывания пропускаются при разборе. Поле authorsVerified показывает, есть ли идентификатор источника у каждого наблюдения. Уникальный текст сам по себе не доказывает независимость автора. Проверки: ReviewTasteTest, CatalogPersistenceTest через tools/e2e.ps1 и node --test tools/import-tasty-reviews.test.mjs.

Сводка по отзывам в review-features.summary содержит статус, категорию, распределение LOW/MEDIUM/HIGH и счётчики для каждой шкалы. На товар и шкалу приходится максимум один голос от каждого различимого аккаунта. Противоречащие друг другу голоса одного аккаунта исключаются. UNKNOWN означает меньше трёх согласованных внутри аккаунта голосов; CONFLICTED — три или больше при отсутствии группы с долей не менее 2/3. При достижении порога статус CONSENSUS и поле bucket содержат категорию.

Импорт передаёт только явно опубликованный числовой data-author-id, если он есть. Бэкенд хранит хеш ID. Разные ID для одного нормализованного текста оставляют текст без независимого голоса. Отзывы V8 и тексты без ID остаются наблюдениями и увеличивают только unverifiedObservations. На проверенной карточке «Бразилия Игуасу» видимая порция не содержала стабильного ID, поэтому она сама не формирует консенсус. Пороговые сценарии проверены на синтетических данных, а не заявлены как консенсус реальных покупателей.
